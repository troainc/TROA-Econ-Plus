# Configuration Guide

The complete XML schema is [`TROA-Econ-Plus.cfg.example`](../TROA-Econ-Plus.cfg.example). Copy individual settings into the config generated by the plugin; do not replace a live config blindly during an upgrade. Keep an untouched backup before editing.

Settings only take effect when the installed Econ+ build supports them. The public example currently documents the v1.8.0-alpha schema. Unknown or newer settings do not add features to an older DLL.

## Editing rules

- Stop Torch before editing the file directly. Save valid XML with one `<EconPlusConfig>` root.
- Keep every opening and closing tag paired. XML special characters in text values must be escaped (`&amp;` for `&`).
- Change only the settings you intend to change; preserve the rest of your generated config.
- Use `!econadmin reload` when supported. Check the response and Torch log; restart Torch if the changed setting is only loaded during startup.
- Never put real webhook URLs, bot tokens, or private account data in a public issue or config upload.

## Safe initial choices

The full sample contains many optional economy systems. A conservative first setup is:

1. Keep `UseInternalAccounts=true`; Econ+ owns the balances.
2. Decide whether `ImportKeenBalanceOnFirstUse=true` should seed a new account from the current Keen balance. This is a one-time first-use action.
3. Keep `EnablePlayerTransfers=true` and set fees/taxes to zero until you have reviewed treasury routing.
4. Choose whether you want commodity trading. If yes, use the sample market settings, test a tagged station, and verify physical inventory delivery.
5. Leave government tax, territories, insurance, contracts, government bonds, and Nexus synchronization disabled until you have set up their treasury, limits, and administration.
6. Back up the world, config, and full Econ+ data folder before opening the feature to players.

## Main settings by area

### Accounts and transfers

| Setting | Purpose |
|---|---|
| `UseInternalAccounts` | Uses Econ+'s persistent accounts as the authoritative balance source. |
| `ImportKeenBalanceOnFirstUse` | Performs a one-time import when a Steam ID's Econ+ account is first created. |
| `MirrorBalancesToKeen` | Enables the optional compatibility mirror to Keen banking. |
| `NewAccountStartingCredits` | Sets the starting balance of a newly created account. |
| `EnablePlayerTransfers` | Enables player-initiated payments. |
| `MinimumTransferCredits`, `MaximumTransferCredits`, `TransferCooldownSeconds` | Bound payment size and rate. |
| `TransferFeePercent`, `PlayerTransferTaxPercent` | Apply separate transfer fee and tax percentages. |
| `MaximumCombinedChargeCredits` | Caps combined fee/tax; `0` means no cap. |
| `ChargeDestination` | Sends charges to the configured treasury or sinks them. |
| `TreasuryFactionTag` | Selects the faction tag for treasury-routed credits. Create the matching Econ+ faction account first. |
| `ExemptSteamIds`, `ExemptSourcePlugins` | Exempts specific player IDs or API consumers from configured charges. Keep these lists private and reviewed. |

### Commodity market and stations

| Setting | Purpose |
|---|---|
| `EnableCommodityMarket` | Enables the physical-item market. |
| `AutoScanItemsOnLoad` | Scans registered vanilla and mod item definitions on load. |
| `MarketItemTypes` | Optional whole-market allowlist of item types; empty includes all categories. |
| `StationNameTag`, `StationRadiusMeters`, `RequireStationProximity` | Define named trade stations and player proximity requirements. |
| `EnablePhysicalDelivery` | Grants/removes physical inventory items during trades; test capacity and item handling. |
| `DefaultItemBasePrice`, `MarketPriceFloorDivisor`, `MarketPriceCeilingMultiplier`, `ScannedItemElasticity`, `ScannedItemDemandScale`, `MarketPollSeconds`, `MarketDecayPercentPerPass` | Set starting prices and market movement bounds/pace. |
| `MaximumTradeQuantity`, `MarketMakerUsesTreasury` | Bound quantities and select the configured market funding behavior. |

Use `TROA-Econ-PlusData/MarketCatalog.csv` to find exact server item symbols and category names. Do not guess a modded item's symbol.

### Investment exchange, shops, and orders

`EnableInvestmentExchange` controls the exchange. `EnablePlayerShops` controls peer listings. `EnableAlerts` and `EnableLimitOrders` control price alerts and standing orders; limits such as `MaxAlertsPerPlayer`, `MaxOrdersPerPlayer`, `MaxListingsPerPlayer`, and `MaximumInvestQuantity` bound use. Review fees and expiry settings before enabling them on a production server.

### Factions, payroll, taxes, and government

Faction accounts and faction payroll are separate from the global scheduled payout engine. Set `EnableFactionAccounts` and `EnableFactionPayroll` according to your policy, and review `FactionApprovalThresholdCredits`, `FactionDailySpendingLimitCredits`, payroll initiator policy, cooldown, recipient cap, and per-member amount cap.

`EnablePayroll` controls administrator-created scheduled programs; `RequireFundedTreasuryPayouts` requires the global treasury to cover a payout. Government tax is separately controlled by `EnableGovernmentTax` and requires `GovernmentFactionTag` plus a funded faction treasury. Territories, tariffs, royalties, citizen stipends, charters, elections, and bonds each have their own feature switches. Keep them off until their governance and funding model are clear.

### Insurance, contracts, credit, and risk

Insurance, contracts, credit products, player loan applications, and risk controls have separate settings. Review each maximum, cooldown, interval, expiry, funding source, and enforcement effect. In particular, loans and scheduled payments must have a funded treasury; contracts hold the poster's funds in escrow; insurance claims require an authorized loss workflow. Use the [Server Owner Setup Guide](SERVER-OWNER-SETUP.md#optional-features) before enabling these systems.

### LCDs and messaging

`EnablePlayerLcdDisplays`, `LcdNameTag`, `LcdRefreshSeconds`, and `DefaultLcdTemplate` control account panels. A block name can include `[ECON+]`; configure each panel's `Template=` in Custom Data. `LcdUseSprites` and `LcdDefaultRenderMode` select the renderer; use `Render=Text` per panel if a particular surface does not support sprite drawing. `Style=false` keeps manual panel styling. The full panel procedure and supported templates are in the [Player Guide](PLAYER-GUIDE.md#lcd-panels).

`EnableHudNotifications` and `EnableInGameMessages` control player messages. Message-specific switches tune payment, schedule, and loan reminders. These do not affect accounting.

### Discord and multi-server

Discord webhook settings send optional transaction notifications. Keep `EnableDiscordWebhook=false` until you have a private HTTPS webhook URL. Notification failures do not change a transaction. Private banking webhook settings should only be configured in trusted server files.

Keep `EnableNexusSynchronization=false` for one server. A multi-server deployment needs unique `NexusServerId` values, exactly one authority server ID, and an authenticated transport adapter. These XML settings alone do not create that transport.
